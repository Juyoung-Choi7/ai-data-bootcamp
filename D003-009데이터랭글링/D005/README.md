## 4. 시간 패턴 (리샘플링에서 읽은 것)
- 트래픽이 가장 몰린 시간대: 2025-03-07 22:00:00시  
   → hourly_traffic.sort_values(ascending=False).head(3) 연산 결과
- 24시간 중 트래픽이 가장 몰리는 시간대: 22시
   → hour_traffic.sort_values(ascending=False).head(3) 연산 결과
- 요일/시간대 특징: 
    - **요일별**로는 목요일(225건)·월요일(221건)·금요일(221건)이 상대적으로 많고,
    수요일(198건)이 가장 적음. 다만 요일 간 차이(198~225건)는 크지 않아
    특정 요일에 뚜렷하게 쏠리는 패턴은 아님.
    → **근거**: [dow_traffic = log_ts["dow"].value_counts().sort_index()] 연산 결과
    (월 221 / 화 215 / 수 198 / 목 225 / 금 221 / 토 212 / 일 208)

  - **시간대별**로는 22시(82건)·1시(81건)·7시(81건)에 요청이 집중되며,
    낮 시간대(12~16시)보다 심야·새벽(0~1시, 7시)과 저녁(22시)에 오히려
    트래픽이 몰리는 경향을 보임. 이는 일반적인 "낮 활동 시간대에 몰린다"는
    통념과 다른 패턴으로, 심야 배치 작업이나 해외 사용자 접속, 또는
    프로모션 알림 발송 시각과 연관되었을 가능성이 있음.
    → **근거**: [hour_traffic = log_ts["hour"].value_counts().sort_index()] 연산 결과,
    Hour of Day Traffic Pattern 막대그래프

## 심화 과제 (선택)

- [x] 특정 IP의 요청 수를 세어, 비정상적으로 많은 요청을 보낸 IP가 있는지 
      찾아보고 근거를 적었다.
      
  전체 118개 IP의 요청 수는 평균 12.7건(표준편차 3.3건)으로 대부분 고른 분포를
  보였으나, IP `198.51.100.41`은 24건으로 임계값(평균+3×표준편차 ≈ 22.6건)을
  초과한 유일한 IP로 확인됨. 일반 사용자 대비 약 2배 많은 요청을 보낸 것으로,
  봇/크롤러 또는 반복 스크래핑 가능성이 있어 추가 확인이 필요함.
  → **근거**: [ip_traffic = logs["ip"].value_counts()] 및 
    [평균+3×표준편차 임계값] 기준 필터링 결과

- [x] 오류 응답(4xx·5xx)이 가장 잦은 경로(path)를 찾아, 운영팀에 무엇을 
      제안할지 적었다.

  오류율이 가장 높은 경로는 `/checkout`(27.95%)으로, 전체 요청 5건 중 
  1건 이상이 오류로 이어지고 있음. 그 다음으로 `/products/456`(25.15%), 
  `/cart`(24.86%) 순으로 오류율이 높음. 
  → **근거**: [error_rate_by_path = (error_by_path / total_by_path * 100)] 
    연산 결과
  → **운영팀 제안**: `/checkout`은 결제 완료 직전 단계로, 오류율이 가장 높다는 것은 
    구매 전환에 직접적인 손실로 이어질 수 있음. 결제 API 응답 코드(4xx: 입력값 오류, 
    5xx: 서버 오류)를 세분화하여 원인 파악 및 우선 점검을 제안함. 아울러 
    `/products/456` 상품 페이지의 높은 오류율도 함께 점검하여, 특정 상품 
    페이지 로직 결함 여부를 확인할 필요가 있음.
